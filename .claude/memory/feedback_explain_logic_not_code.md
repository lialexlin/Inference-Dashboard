Alex is non-technical. When explaining infra, tooling, or code work, explain what actually happens and why — the logic and the outcome. Never walk him through the code.

**Direct quote (2026-06-30):** "don't tell me codes.. never try to explain the codes. i don't care about the code. i care about what actually happens, tell me what's the logic."

**How to apply:**
- Describe behavior and effect: "the script pulls the latest marks, drops write-offs, and writes one row per fund" — not the functions or syntax that do it.
- No code blocks, no function/variable names, no line-by-line walkthrough unless he explicitly asks to see code.
- If a fix matters, say what was broken and what it does now, in plain outcome terms.
